# نظام CRM — شخصيات المستخدمين

> **التوأم:** `User_Personas_EN.md` — لازم الاتنين يفضلوا متطابقين دلاليًا.

## الغرض

المستند ده بيعرّف أدوار النظام التمانية لتصميم المنتج وتصميم المسارات واختبار القبول. ومبني على `CRM_Documentation_EN.md` و `MVP_Build_Plan_EN.md` بس.

استخدمه قبل عمل نظام التصميم وأي شاشة مرتبطة بدور. **وهو مش بيعمل صلاحيات: مصفوفة الصلاحيات في مستندات الـ CRM هي المرجع.**

## سياق مشترك

- الـ CRM داخلي، على سيرفر الشركة، وبيستخدمه من عشرات لمئات الموظفين.
- العربي والإنجليزي، بما فيهم RTL/LTR، مطلوبين من أول إصدار.
- أدوار المكتب بتستخدم الويب على الديسك توب أساسًا. والمبيعات الخارجية بتستخدم الموبايل PWA والديسك توب.
- النظام أونلاين بس. والدخول من برّه محتاج VPN؛ ولازم تبقى فيه حالة واضحة لانقطاع الـ VPN.
- أيام الشغل من الأحد للخميس.

## P-01 — Super Admin

| العنصر | التعريف |
|---|---|
| الدور | المطوّر ومدير النظام الكامل؛ **مخفي عن كل المستخدمين العاديين**. |
| الهدف الأساسي | يخلّي النظام آمن ومتاح ومظبوط وقابل للاسترجاع. |
| المسؤوليات | دورة حياة المستخدمين؛ الأدوار والصلاحيات الديناميكية؛ الإعدادات؛ أسعار الصرف؛ الحدود والـ SLAs؛ الـ audit؛ الداتابيز؛ الطوابير؛ النسخ الاحتياطي؛ التكاملات؛ الصيانة؛ صحة النظام. |
| الشاشات | 22 شاشة إدارية: لوحة النظام، المستخدمين، الصلاحيات، الإعدادات، العملات وأسعار الصرف، الحدود والـ SLAs، الداتابيز، الـ audit، مركز الأخطاء، مراقب الطوابير، مركز الإشعارات، النسخ الاحتياطي، التخزين، الأداء، الأمن، الجدولة، الـ feature flags، التكاملات، مدير الـ API، وضع الصيانة، أدوات المطوّر، وتحليلات النظام. |
| المعلومات المحتاجة | صحة الخدمات، وحالة النسخ الاحتياطي، والمهام الفاشلة، والأخطاء، والجلسات النشطة، والتخزين، وقِدَم أسعار الصرف، وتاريخ الـ audit، وتاريخ الإعدادات. |
| الإجراءات الحرجة | إنشاء/تعطيل/تفعيل المستخدمين؛ إعادة تعيين كلمة السر؛ الخروج الإجباري؛ تغيير الدور؛ `Login As`؛ ضبط الأدوار والإعدادات والعملات والحدود والـ feature flags ووضع الصيانة. |
| الحواجز | `Login As` **لازم يتسجّل**. وكل تغيير في الإعدادات بيتسجّل في الـ audit. والـ Super Admin **عمره ما يظهر** في قوائم الموظفين. |
| أثر التصميم | لوحة تشغيلية كثيفة، وحالة صريحة لكل تبعية، وتأكيد للإجراءات غير القابلة للتراجع، ومراجع audit ظاهرة، وإجراءات فشل/إعادة محاولة واضحة. |

## P-02 — CEO

| العنصر | التعريف |
|---|---|
| الدور | مراقب خارجي بصلاحية **قراءة فقط** على مستوى الشركة. |
| الهدف الأساسي | يفهم أداء الشركة من غير ما يشغّل الـ CRM اليومي. |
| المسؤوليات | مراجعة لوحات المعلومات والعملاء وملفات عروض الأسعار والتقارير؛ **والتعليق على التقارير بس**. |
| الشاشات | لوحة المعلومات، العملاء، عروض الأسعار (قراءة)، التقارير. |
| المعلومات المحتاجة | الإيراد لكل عملة، والربح، وأعداد العملاء والصفقات، والاتجاهات العامة، والتقارير المستلمة. |
| الإجراءات الحرجة | عرض السجلات، وتنزيل ملفات عروض الأسعار الموجودة، وتصدير التقارير، والتعليق على التقارير. |
| الحواجز | **مفيش drill-down** في لوحات المعلومات. **مفيش** إنشاء ولا تعديل ولا موافقة ولا اعتماد ولا إرجاع ولا تغيير حالة. والـ CEO **بينزّل PDF موجود وعمره ما يولّد جديد**. |
| أثر التصميم | ملخصات تنفيذية الأول، وتنقل مختصر، وحالة "قراءة فقط" واضحة، ومفيش أزرار توحي بصلاحية تعديل. |

## P-03 — Manager

| العنصر | التعريف |
|---|---|
| الدور | أعلى سلطة تشغيلية بنطاق على مستوى المؤسسة. |
| الهدف الأساسي | يتحكم في أداء المبيعات والمشتريات، ويفك التعطيلات، ويحافظ على جودة البيانات. |
| المسؤوليات | إدارة العملاء والصفقات وعروض الأسعار والموافقات والموظفين في حدود الأدوار المسموحة والزيارات والتقارير والأرشيف وأسعار الصرف ورؤية audit الفريق. |
| الشاشات | لوحة المعلومات، الموظفين، العملاء، الطلبات/الصفقات، عروض الأسعار، الموافقات، زيارات الفريق، الكتالوج، الموردين، عروض الموردين، التقارير، الأرشيف. |
| المعلومات المحتاجة | العروض المعلّقة والمرتجعة، وعدد الموافقات الذاتية، وخط الصفقات، والربح/التوفير، وحمل الموظفين، والتقارير، والشغل الراكد، والسجلات المؤرشفة/لموظفين معطّلين. |
| الإجراءات الحرجة | إسناد العملاء/الصفقات، والموافقة/الرفض/التعديل والموافقة على العروض، وتأكيد إتمام التسليم، وإنشاء حسابات الموظفين المسموحين، وتعطيل الحسابات، وضبط أسعار الصرف، والأرشفة/الاسترجاع، واعتماد/إرجاع/التعليق على التقارير. |
| الحواجز | **مش بيقدر يعمل** حسابات Manager أو CEO أو Super Admin. وتعديلات الضريبة أو الهامش **لازم تتسجّل في الـ audit**. والموافقة الذاتية لازم تكون صريحة ومتتبَّعة. |
| أثر التصميم | لوحة تشغيلية بـ drill-down، وفلاتر حسب الموظف/الفريق/الفترة، وطابور موافقات بمؤشر مدة الانتظار، وأرشفة/استرجاع جماعي، وتأكيد وتغذية راجعة قوية للـ audit. |

## P-04 — Team Leader

| العنصر | التعريف |
|---|---|
| الدور | مالك فريق مبيعات بصلاحية على نطاق الفريق. |
| الهدف الأساسي | يوزّع الشغل الداخل، ويحافظ على جودة عروض الأسعار، ويخلّي صفقات الفريق ماشية. |
| المسؤوليات | امتلاك عملاء وصفقات الفريق، وإسناد مالكي المبيعات، ومراجعة العروض، والموافقة/رفض الطلبات المدخّلة من الموظفين، ورؤية تقارير الفريق، وإدارة أرشيف الفريق. |
| الشاشات | لوحة المعلومات، فريق المبيعات، العملاء، عملائي، الطلبات/الصفقات، عروض الأسعار بما فيها غير المكتملة، الموافقات، الكتالوج، الموردين، عروض الموردين، التقارير، الأرشيف. |
| المعلومات المحتاجة | الصفقات المسندة والحالية، والطلبات المعلّقة، وطابور عروض الفريق، والعروض المرتجعة والمعتمدة ذاتيًا، وحمل الموظفين، والصفقات الراكدة، والعملاء المستوردين غير المكتملين، وتقارير الفريق. |
| الإجراءات الحرجة | إنشاء/إسناد/تعديل عملاء وصفقات الفريق، والموافقة/رفض الطلبات، والموافقة/التعديل والموافقة/إرجاع العروض، وإسناد المناطق حيث مسموح، وأرشفة/استرجاع عملاء الفريق، واعتماد/إرجاع/التعليق على التقارير المستلمة. |
| الحواجز | النطاق **للفريق بس** حيث المصفوفة بتقول `Team`. **ومفيش تصعيد تلقائي** بيحل محل مراجعته. والعروض المرتجعة محتاجة ملاحظة؛ والموافقة على عرضه هو **لازم تتعلّم وتتسجّل**. |
| أثر التصميم | فلاتر مركزها الفريق افتراضيًا، وتجميع حسب الموظف، وإبراز مدة انتظار الموافقة، ووضوح حمل الشغل، وإعادة إسناد سريعة من غير فقدان تاريخ العميل. |

## P-05 — Outdoor Supervisor

| العنصر | التعريف |
|---|---|
| الدور | مشرف الزيارات الخارجية؛ **مسؤوليته بتنتهي عند تسليم العميل**. |
| الهدف الأساسي | يراقب النشاط الخارجي ويضمن إن الزيارات متسندة ومسجّلة صح. |
| المسؤوليات | عرض الزيارات الخارجية، وإنشاء/تعديل عملاء الزيارات والصفقات في النطاق الخارجي، وإسناد المناطق، وإرسال/استلام التقارير، وعرض حالة التسليم. |
| الشاشات | زيارات اليوم، سجل الزيارات، العملاء (عملاء الزيارات)، الطلبات (نطاق خارجي)، الكتالوج، التقارير. |
| المعلومات المحتاجة | زيارات اليوم، ونتايج الزيارات، وأسباب رفض الشركات، والزيارات المفتوحة وتواريخ المتابعة، والتسليمات الناجحة، وتقارير الفريق الخارجي. |
| الإجراءات الحرجة | إنشاء/تعديل سجلات الزيارات والعملاء والصفقات في النطاق الخارجي، وتغيير حالة الصفقات الخارجية، وإسناد مناطق الزيارات، وإنشاء التقارير، واعتماد/إرجاع/التعليق على التقارير المستلمة. |
| الحواجز | **مش بيقدر** يوافق/يرفض الطلبات، ولا يسند موظفي مبيعات، ولا يأكّد إتمام التسليم، ولا يوصل لصفقة **بعد** ما تتسلّم. وبيشوف سجلات الفريق الخارجي بس. |
| أثر التصميم | نظرة عامة محورها الزيارة، وعلامات واضحة للنتيجة والتسليم، وأدوات صفقات في النطاق الخارجي من غير أزرار موافقة أو إسناد، وصفقة بتختفي بشكل نظيف عند التسليم. |

## P-06 — Outdoor Sales

| العنصر | التعريف |
|---|---|
| الدور | مندوب ميداني بيسجّل الزيارات وبيكمّل كمالك مبيعات. |
| الهدف الأساسي | يخلّص الزيارات بأقل كتابة، ويحوّل الزيارات الناجحة لشغل مؤهل، ويدير نشاطه. |
| المسؤوليات | عرض/تسجيل زياراته، وإنشاء/تعديل عملاءه وصفقاته، وبناء وإرسال عروضه، وتسجيل ردود العملاء، واستخدام بيانات الكتالوج والموردين. |
| الشاشات | زيارات اليوم، سجل الزيارات، العملاء، عروض الأسعار، الكتالوج، الموردين، عروض الموردين؛ موبايل وديسك توب. |
| المعلومات المحتاجة | الزيارات المسندة، وحالة فورم الزيارة، وعملاءه وصفقاته وعروضه، وعروض الموردين، وتوافر المنتجات والتحذيرات، وحالة العرض الحالي. |
| الإجراءات الحرجة | استكمال فورمات الزيارات؛ إنشاء/تعديل سجلاته؛ إرسال عروضه للموافقة؛ إرسال العروض المعتمدة؛ تسجيل ردود العملاء؛ **حذف عرضه في `Draft` بس**. |
| الحواجز | فورم الزيارة فيه **تلات حقول إجبارية بالظبط**: اسم الشركة، الشخص المسؤول، النتيجة. والطلب الناجح بيتوجّه للـ Team Leader وبيتعلّم "تم" للموظف الخارجي. **ومفيش وصول لعروض برّه نطاق `Own`**. |
| أثر التصميم | مسار موبايل أولًا، وأدوات فورم مختصرة، وحالة اتصال/VPN واضحة، وحماية المسودة أثناء انقطاع قصير، وإبراز تحذيرات السعر والمنتج. |

## P-07 — Indoor Sales

| العنصر | التعريف |
|---|---|
| الدور | موظف مبيعات بيدير عملاءه خلال دورة الصفقة وعرض السعر. |
| الهدف الأساسي | ينقل طلبات العملاء المسندة له من التواصل لعرض السعر ورد العميل بدقة. |

| الشاشات | العملاء، الصفقات، عروض الأسعار، الكتالوج، الموردين، عروض الموردين، التقارير. |

| أثر التصميم | طابور شغل محوره الصفقة، وتقدّم حالة واضح، وباني عرض بحسابات مؤكَّدة من السيرفر، وتحذيرات موردين/منتجات ظاهرة، وتاريخ النسخ. |

## P-08 — Procurement

| العنصر | التعريف |
|---|---|
| الدور | المفاوض على الصفقات المسندة بعد ما تتكسب. |
| الهدف الأساسي | يقلّل تكلفة المورد، ويسجّل التوفير بدقة، ويوصّل الصفقة المسندة للتسليم. |
| المسؤوليات | مراجعة الصفقات والعروض المسندة، وتسجيل عروض الموردين، والتفاوض على الأسعار، وتسجيل النجاح/الفشل والتوفير، ومتابعة الشراء والتسليم، وإرسال التقارير. |
| الشاشات | الصفقات المسندة، سجل التفاوض، عروض الأسعار، الكتالوج، الموردين، عروض الموردين، التقارير. |
| المعلومات المحتاجة | نطاق الصفقة المسندة، وشروط وصلاحية عروض الموردين، والتكلفة الأصلية، والتكلفة بعد التفاوض، والتوفير، والربح النهائي، وحالة التسليم، وبيانات تقرير المشتريات. |
| الإجراءات الحرجة | تعديل الصفقات المسندة، وإنشاء مفاوضات، وتسجيل التوفير أو أسباب الفشل، وتأكيد `Delivery Complete` للصفقات المسندة، وتوليد/تنزيل ملفات العروض المسموحة، وإنشاء عروض موردين وتقارير. |
| الحواجز | **بيشوف كل البيانات المالية** للشغل المسند له، **بس مش بيعمل عروض للعملاء ولا بيوافق عليها**. والتفاوض الفاشل محتاج سبب؛ والصفقة بتكمّل بالسعر الأصلي. |
| أثر التصميم | مقارنة مالية وسجل تفاوض، وفصل واضح بين التكلفة الأصلية والمتفاوض عليها، ووضوح حساب التوفير/الربح، وتتبع تسليم المهمة. |

## قواعد تصميم عابرة للشخصيات

1. **افرض كل الصلاحيات على مستوى الـ API؛ ظهور الواجهة مش صلاحية.**
2. اعرض السجلات المسموحة لنطاق الدور بس: `Own` أو `Team` أو `All` أو `Out` أو `Asgn`.
3. استخدم الشارات والتحقق داخل الصفحة في الـ MVP؛ مركز الإشعارات الكامل بعد الـ MVP.
4. حافظ على إمكانية التتبع وتاريخ السجلات **من غير كشف بيانات موردين أو بيانات مالية سرية في ملفات العملاء**.
5. **عمرك ما تستخدم ملخصات الشخصيات لتوسيع صلاحيات دور موثّقة.**
